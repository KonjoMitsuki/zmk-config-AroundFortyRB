# 左右の状態LED

| 側 | 状態 | LED |
|---|---|---|
| 左 | クリスタ OFF | 消灯 |
| 左 | クリスタ ON | 紫（マゼンタ） |
| 右 | AML自動発動 OFF、マウスレイヤーも無効 | 消灯 |
| 右 | AML自動発動 ON、マウスレイヤー待機中 | 緑 |
| 右 | AMLマウスレイヤーが有効 | 水色（シアン） |

クリスタとAMLの状態は独立して表示する。Settingsなど、より上位の
レイヤーを開いても表示は変わらない。起動時、接続状態、低電池の表示は
従来のRGBウィジェットが一時的に表示し、その後に現在の状態色へ戻る。
AML OFF操作はAML-OnとAMLマウスレイヤーだけを解除し、クリスタと
Windows/macOSのベースレイヤーを維持する。

右が実際のクリスタレイヤーの状態を読み、ZMK v0.3のsplit behaviorコマンドで
左へ送る。切替時に送信し、2秒ごとに再送して再接続や左の再起動にも対応する。
左は切断を検出したら消灯する。タップ回数から推測しないため、長押し切替、
Settingsからの切替、OS切替によるレイヤー解除も反映する。

## ビルド・書き込み

この変更は**左右両方**をビルドし、両方へ書き込む必要がある。
同梱のGitHub Actionsはルートの`zephyr/module.yml`を検出して自動で
カスタムモジュールを読み込む。ローカルビルドでは通常の引数に
`-DZMK_EXTRA_MODULES=/absolute/path/to/zmk-config-AroundFortyRB`を加える。
モジュール依存の取得には、変更後のmanifestで`west update`を実行する。

RGBウィジェットには任意の常時表示色を設定する公開APIがないため、
`src/aroundforty_status_led.c`は既存のメッセージキューと復帰色を利用する。
GPIOを別処理から直接操作せず、電池・接続表示との競合を避ける。
互換性のためウィジェットを`8756cb7b8114069fa3c25c6f6c990f24988fceff`
に固定し、CMakeでも対象ソースのSHA-256を確認する。
依存モジュールを更新するときはキューの構造と復帰色の扱いを再確認する。

実機ではクリスタ／AMLの各ON・OFFの組合せ、Settingsを開いている間、
OS切替、左だけの再起動、左右の切断・再接続、電池・接続表示後の復帰を確認する。
